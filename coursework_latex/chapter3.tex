\subsection{Вёрстка HTML страниц}

Разработка пользовательского интерфейса началась с создания базового шаблона \texttt{base.html}, который определяет общую структуру всех страниц приложения. Шаблон включает:
\begin{itemize}
    \item заголовок страницы с динамическим title;
    \item подключение Bootstrap 5.3 (CSS и JS) через CDN;
    \item подключение кастомных стилей \texttt{style.css};
    \item навигационную панель (navbar), содержимое которой зависит от роли пользователя;
    \item блок для отображения flash-сообщений (уведомлений);
    \item основную область контента (блок \texttt{content});
    \item футер с копирайтом.
\end{itemize}

На основе базового шаблона были свёрстаны следующие страницы:
\begin{itemize}
    \item \texttt{auth/login.html} --- страница входа (форма с полями username и password);
    \item \texttt{auth/register.html} --- страница регистрации (выбор роли: владелец/участник, поле кода семьи для участников);
    \item \texttt{dashboard/owner\_dashboard.html} --- главная страница владельца семьи с дашбордом;
    \item \texttt{dashboard/member\_dashboard.html} --- главная страница участника семьи;
    \item \texttt{dashboard/admin\_dashboard.html} --- панель администратора;
    \item \texttt{transactions.html} --- страница управления транзакциями с таблицей, фильтрацией и формой добавления;
    \item \texttt{categories.html} --- страница управления категориями (только для владельца);
    \item \texttt{members.html} --- страница управления участниками семьи;
    \item \texttt{profile.html} --- страница профиля пользователя.
\end{itemize}


\subsection{Реализация модуля авторизации}

Модуль авторизации реализован с использованием расширений \texttt{Flask-Login} (управление сессиями) и \texttt{bcrypt} (хэширование паролей) через методы \texttt{set\_password} и \texttt{check\_password} в модели \texttt{User}.

Регистрация пользователя реализована с учётом ролевой модели:
\begin{itemize}
    \item При выборе роли \textbf{«Владелец»} автоматически создаётся новая семья с уникальным названием и генерируется 6-значный код-приглашение. Пользователь становится первым участником этой семьи.
    \item При выборе роли \textbf{«Участник»} пользователь должен ввести код-приглашение существующей семьи. Система проверяет корректность кода и добавляет пользователя в соответствующую семью.
\end{itemize}

Регистрация пользователя реализована в маршруте \texttt{/auth/register} с учётом ролевой модели:
\begin{itemize}
    \item При выборе роли \textbf{«Владелец»} автоматически создаётся новая семья с названием «Семья \{username\}» и генерируется 6-значный код-приглашение (формата FAM-XXXXXX). Пользователь становится владельцем этой семьи. Также автоматически создаются категории по умолчанию: Продукты, Транспорт, Коммунальные услуги, Зарплата, Подработка, Кафе и рестораны, Развлечения, Одежда.
    \item При выборе роли \textbf{«Участник»} пользователь должен ввести код-приглашение существующей семьи. Система проверяет корректность кода и добавляет пользователя в соответствующую семью с ролью \texttt{'member'}.
\end{itemize}

Аутентификация выполняется через маршрут \texttt{/auth/login} с использованием Flask-Login. После успешного входа пользователь перенаправляется на дашборд, соответствующий его роли: \texttt{/dashboard/admin} для администратора, \texttt{/dashboard/owner} для владельца, \texttt{/dashboard/member} для участника. Доступ к страницам контролируется декоратором \texttt{@login\_required}, а для разграничения прав по ролям используется проверка \texttt{current\_user.role}. 

% Для администратора создана отдельная учётная запись по умолчанию с данными: логин \texttt{'admin'}, пароль \texttt{'admin123'}. При первом запуске приложения база данных автоматически инициализируется и создаётся администратор. Администратор имеет доступ к панели администратора \texttt{/dashboard/admin} и может просматривать всех пользователей системы, а также все транзакции для отладки.


\subsection{Реализация CRUD-интерфейса}

CRUD-интерфейс (Create, Read, Update, Delete) реализован для трёх основных сущностей: транзакции, категории и участники. Все операции выполняются через веб-формы.

\subsubsection{Управление транзакциями}

Для работы с транзакциями создана модель \texttt{Transaction}. Связь с чеком реализована через модель \texttt{Receipt}.

Реализованы следующие маршруты и API-эндпоинты:
\begin{itemize}
    \item \texttt{GET /transactions} --- отображение списка транзакций с возможностью фильтрации по поисковому запросу и диапазону дат;
    \item \texttt{POST /add\_transaction} --- добавление новой транзакции;
    \item \texttt{POST /edit\_transaction} --- редактирование существующей транзакции;
    \item \texttt{POST /api/delete\_transaction/<int:id>} --- удаление транзакции;
    \item \texttt{GET /api/get\_transaction/<int:id>} --- получение данных транзакции для редактирования.
\end{itemize}

При добавлении транзакции сумма всегда вводится как положительное число, затем на основе типа категории определяется знак: для категорий типа \texttt{'expense'} сумма становится отрицательной, для \texttt{'income'} --- остаётся положительной. Пользователь с ролью \texttt{'owner'} может добавлять транзакции для любого члена семьи, участник --- только для себя.

\subsubsection{Управление категориями}

Для реализации CRUD-функционала категорий создана модель \texttt{Category}. Категории доступны только для владельца семьи через маршрут \texttt{/categories}. Владелец может создавать, редактировать и удалять категории. При удалении категории все связанные с ней транзакции и чеки также удаляются для сохранения целостности данных.

Для установки лимитов на категории используется модель \texttt{CategoryLimit}. Установка лимита реализована через маршрут \texttt{/set\_category\_limit}. На странице категорий отображается текущий лимит для каждой категории (если установлен).

\subsubsection{Управление участниками}

Управление участниками семьи доступно владельцу через маршрут \texttt{/members}. На этой странице отображается список всех членов семьи с их данными и установленным бюджетом. Реализованы следующие возможности:
\begin{itemize}
    \item \textbf{Просмотр} --- отображение всех участников семьи с возможностью поиска по имени;
    \item \textbf{Установка бюджета} --- владелец может установить персональный бюджет для любого участника через модальное окно;
    \item \textbf{Удаление участника} --- владелец может удалить участника из семьи (кроме самого себя и владельца). При удалении участника все его транзакции и чеки также удаляются. Реализовано через API-эндпоинт \texttt{/api/delete\_member/<int:id>};
    \item \textbf{Генерация кода приглашения} --- владелец может сгенерировать новый код приглашения для добавления новых участников через маршрут \texttt{/generate\_invite\_code}.
\end{itemize}

Все операции управления участниками защищены проверкой роли: только пользователь с ролью \texttt{'owner'} имеет доступ к этому функционалу.


\subsection{Реализация обработки и анализа данных}

Обработка и анализ данных реализованы на уровне моделей и маршрутов приложения. 

В модели \texttt{User} добавлены методы \texttt{get\_transactions()}, \texttt{get\_total\_income()}, \texttt{get\_total\_expense()}, \texttt{get\_balance(period)} и \texttt{get\_category\_breakdown()}, которые выполняют фильтрацию транзакций по периодам (день, неделя, месяц) и агрегацию сумм.

\subsubsection{Агрегация данных для дашбордов}

Для дашбордов владельца и участника семьи (\texttt{/dashboard/owner}) реализована следующая логика:
\begin{itemize}
    \item Общая сумма доходов и расходов за выбранный период (день/неделя/месяц) вычисляется с использованием методов модели \texttt{User};
    \item Остаток бюджета рассчитывается как разница между установленным бюджетом пользователя и суммой расходов за период;
    \item Расходы по категориям группируются для круговой диаграммы через словарь \texttt{expense\_by\_category};
    \item Динамика баланса строится на основе накопленного итога по интервалам (для дня --- по часам, для недели --- по дням, для месяца --- по дням месяца);
    \item Сводная таблица по участникам формируется путём агрегации данных для каждого члена семьи.
\end{itemize}

Период (день/неделя/месяц) выбирается пользователем через параметр \texttt{?period=} в URL, данные пересчитываются при перезагрузке страницы.

\subsection{Реализация работы с файлами}

Модуль работы с файлами обеспечивает прикрепление чеков к транзакциям.

\subsubsection{Загрузка и хранение чеков}

При добавлении или редактировании транзакции пользователь может загрузить файл чека. Реализована следующая логика:
\begin{itemize}
    \item Допустимые форматы: изображения (.jpg, .jpeg, .png) и PDF;
    \item Максимальный размер файла: 16 МБ;
    \item Файл сохраняется на сервере в папке \texttt{uploads/} с использованием \texttt{secure\_filename} для безопасного именования;
    \item В таблице \texttt{Receipt} сохраняется путь к файлу (\texttt{filepath}) и связь с транзакцией (\texttt{transaction\_id});
    \item При удалении транзакции связанный с ней файл чека также удаляется с диска.
\end{itemize}

Владелец семьи и администратор могут просматривать и удалять чеки любых транзакций. Участник имеет доступ только к своим чекам. Просмотр чека реализован через API-эндпоинт \texttt{/api/get\_receipt/<int:id>}, который возвращает URL файла для отображения в модальном окне.


\subsection{Реализация системы визуализации}

Для наглядного отображения финансовой аналитики используется библиотека Chart.js. Визуализация реализована на дашборде на главной странице и включает два типа диаграмм.

\subsubsection{Круговая диаграмма расходов по категориям}

Отображает структуру расходов за выбранный период. Данные для диаграммы формируются на сервере в переменных \texttt{expense\_categories} и \texttt{expense\_amounts}, которые передаются в шаблон и инициализируют JavaScript-массивы. Диаграмма строится с использованием Chart.js тип \texttt{pie}. При наведении на сектор отображается всплывающая подсказка с названием категории, суммой в рублях и процентным соотношением.

\subsubsection{Линейный график динамики баланса}

Показывает изменение накопленного баланса по интервалам выбранного периода. Данные передаются через переменные \texttt{budget\_labels} и \texttt{budget\_balance}. График строится с типом \texttt{line}. Надписи на осях отображаются с указанием валюты.

\subsubsection{Сводная таблица по участникам}

Дополнительно на дашборде владельца реализована таблица с агрегированными данными по каждому участнику семьи: суммы доходов, расходов и баланс за выбранный период. Данные извлекаются из базы данных и отображаются с цветовым кодированием (доходы --- зелёным, расходы --- красным).

Все диаграммы автоматически перестраиваются при изменении периода через параметр URL \texttt{?period=}.
